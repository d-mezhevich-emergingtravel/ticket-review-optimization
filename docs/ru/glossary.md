# 📖 Глоссарий

Термины и сокращения, которые встречаются в документации и SQL-запросах.

## 🎫 Тикеты и компенсации

| Термин | Что означает |
|---|---|
| Тикет | Обращение в CRM. В проекте рассматриваются тикеты по отелям (`product = 'Hotel'`) категорий `Incident` и `Complaint` |
| Money paid | Выплата в тикете: компенсация клиенту или доплата поставщику, отелю |
| Money received | Возврат в тикете: деньги, которые вернул поставщик или отель |
| `payout` | Сумма выплат (Money paid) по тикету в USD |
| `refund` | Сумма возвратов (Money received) по тикету в USD |
| `losses` | Потери по тикету, `payout − refund`, в USD. По ним считаются границы проверки |
| `losses_sum` | Поле `crm.tickets_ticket.losses_sum` с потерями по тикету. В исследовании не используется: у него неполная история изменений |
| Adjust losses | Скорректированные потери по тикету (`adj_losses_sum_usd` в базовом датасете исследования). На них опираются отчёты об источниках и причинах потерь |
| Кредитная линия | Способ оплаты платежа в тикете (`payment_method` = Credit line). Правила ORA в основной выгрузке проверяют, есть ли доплата (Money paid) или возврат (Money received) этим способом |
| Terminated | Статус тикета вместо удаления. Такой тикет не учитывается в системе, компенсаций в нём быть не должно |
| Business decision | Отметка у выплаты: компенсация дана по решению бизнеса, а не из-за чьей-то ошибки |
| Modification | Команда, которая по требованию бизнеса даёт партнёру одностороннюю компенсацию |
| Bug report (BR) | Связанный тикет с разбором ошибки. По нему уточняется виновник и отметка «диспут невозможен» |
| Mismatch report | Связанный тикет о расхождении данных. Тоже используется для определения виновника |
| Log / Com | Поля, которые специалист добавляет в выгрузку во время проверки: что сделано по тикету |

## 🏨 Бронирования

| Термин | Что означает |
|---|---|
| ФОК | Бесплатная отмена бронирования до срока `free_cancellation_before` |
| AB / AS | `amount_buy` — стоимость закупки у поставщика или отеля, `amount_sell` — стоимость продажи клиенту. Разница между ними — наша маржа |
| Supplier penalty | Штраф поставщика или отеля за отмену или изменение бронирования |
| Альтернатива | Замена бронирования: клиента переселяют в другой отель или на другие условия |
| `EXSTRANET` | Сегмент: прямое бронирование у отеля через систему Extranet |
| `SWITCH` | Сегмент: прямое бронирование у отеля или сети через техническую платформу (Chain/Switch) |
| `TPP` | Сегмент: бронирование у поставщика (Third Party Provider) |
| Контур | Юрлицо компании, в котором продано или куплено бронирование: `ru` или `global` (поле `legal_cell`) |
| Деконсолидация | Разделение компании на контуры `ru` и `global` |
| `r2r`, `r2i`, `i2r`, `i2i` | Тип бронирования: первая буква — контур продажи, вторая — контур закупки (`r` — ru, `i` — global). Определяется по юрлицу, поставщику и стране отеля |
| B2A / B2C / CTM | Бизнес-юниты по бренду: B2A — партнёры и агенты, B2C — частные клиенты, CTM — корпоративные клиенты. Ещё есть Wholesaler (источник Hotel (Extr)) и Consolidator (остальные источники) |
| GGA | Поставщик с `supplier_id = 'GGA'`. Его бронирования всегда межконтурные: продажа в `ru` — тип `r2i`, в `global` — `i2r`. Поэтому проверки ORA для него отключаются вместе с `i2r` и `r2i` |
| `user` / `partner` | Кто отменил бронирование: `user` — B2C-клиент, `partner` — B2A-клиент |

## 💸 Действия, которые экономят деньги

| Термин | Что означает |
|---|---|
| Mail, письмо на сверку | Просим финансовый отдел не оплачивать отелю определённое бронирование. Письмо отправляется в том контуре, где бронирование куплено у отеля |
| Dispute, диспут | Отправляем потери на оспаривание поставщику. До решения спора бронирование не оплачивается |
| ORA | Order Reconciliation Amendment, таблица `crm.tickets_orderpriceamendment`. Изменение суммы, которую мы платим поставщику или отелю |
| Синк ORA | Синхронизация ORA: стоимость из CRM записывается в базу данных. Если синк не прошёл, стоимость в базе не изменилась |

## 📐 Метрики исследования

| Термин | Что означает |
|---|---|
| Бакет | Диапазон потерь, по которому группируются тикеты |
| `gross` | Объём изменений компенсаций по модулю, `ABS(paid_delta + received_delta)` в USD |
| Net | Сумма изменений компенсаций с учётом знака |
| ER | Error Rate: доля тикетов бакета, в которых нашли ошибку и внесли изменение (`gross > 0`) |
| AI | Average Impact: медиана `gross` среди тикетов бакета с исправлением |
| RVI | Review Value Index, `ER × AI`: ожидаемая польза в USD от проверки одного тикета бакета |

Подробнее о метриках — в [исследовании](research.md#2-разработка-индексапоказателя-для-отображения-ценности-внесенных-изменений).

## 🔎 Проверка

| Термин | Что означает |
|---|---|
| Выгрузка | SQL-запрос, результат которого специалист проверяет |
| Пул | Все тикеты, попавшие в выгрузку на проверку за период. Используется в [итогах проекта](results.md) |
| `check`, алерт | Поле основной выгрузки. Заполнено, если признаки тикета не сошлись по правилам сегмента. Коды описаны в [основной выгрузке](unloads/main.md#-коды-check) |
| Порог | Границы по `losses`, за которыми тикеты проверяются все: ≥ 500 $ и ≤ −50 $ |
| Лаг | Сколько времени проходит между закрытием тикета и его проверкой |
| OKR | Objectives and Key Results: формат целей и ключевых результатов. Проект оформлен как OKR |
