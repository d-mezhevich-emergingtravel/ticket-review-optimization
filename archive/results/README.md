# Расчёт итогов проекта

Рабочие материалы, по которым посчитаны [итоги проекта](../../docs/ru/results.md): сырые выгрузки специалиста, скрипты, SQL-запросы, финальные датасеты периодов и книги сравнения в Excel. Сохранены целиком, чтобы данные можно было взять отсюда, а не собирать заново.

Расчёт идёт в два этапа:

1. Для каждого периода собирается финальный датасет `result/dataset.xlsx`. Если в сырых данных выделена основная выгрузка (категория `main`), рядом собирается `result/main.xlsx`. Формат у всех периодов один, он описан в разделе [Выход](#выход-resultdatasetxlsx-и-resultmainxlsx).
2. Датасеты двух периодов загружаются в книгу Excel, и Power Query строит сводную таблицу сравнения. Методика описана в [`power_query/README.md`](power_query/README.md).

Сборки и тестов нет. Запросы запускаются вручную в SQL-редакторе, скрипты — локально.

## Структура

| Папка | Что внутри |
|---|---|
| `2025_w33-37/` | период "было" для разделов 1 и 2 итогов: старый workflow, недели 33–37 2025 года |
| `2026_w33-37/` | период "стало" для разделов 1 и 2: тестовый режим, недели 33–37 2026 года |
| `2025_w42-46/` | период "было" для раздела 3: старый workflow, недели 42–46 2025 года |
| `2026_w42-46/` | период "стало" для раздела 3: продуктовый workflow, недели 42–46 2026 года |
| `power_query/` | запрос Power Query `comparison.m`, методика сравнения и книги сравнения |

Какие файлы стоят за каждым разделом [итогов](../../docs/ru/results.md):

| Раздел итогов | Датасеты | Книга сравнения |
|---|---|---|
| 1. Общий датасет: тестовый режим | `result/dataset.xlsx` из `2025_w33-37/` и `2026_w33-37/` | `power_query/compare_w33-37_2025_vs_2026.xlsx` |
| 2. Основная: тестовый режим | `result/main.xlsx` из `2025_w33-37/` и `2026_w33-37/` | `power_query/compare_w33-37_2025_vs_2026_main.xlsx` |
| 3. Продуктовый workflow | `result/dataset.xlsx` из `2025_w42-46/` и `2026_w42-46/` | `power_query/compare_w42-46_2025_vs_2026.xlsx` |

В итогах обе стороны сравнения посчитаны запросом с окном в три недели: `queries/rvi_3w.sql` для 2025 года, `queries/ru/rvi_3w.sql` и `queries/global/rvi_3w.sql` для 2026 года (результаты двух контуров склеиваются). Версии `rvi_1w.sql` и `rvi_5w.sql` с окнами в одну и пять недель лежат рядом.

## Папки периодов

Под каждый период создаётся своя папка `<год>_w<недели>/`. Порядок работы, команды и логика периода описаны в `README.md` его папки, начинать работу с периодом нужно с него.

Папки периодов не зависят друг от друга:

- У всех периодов обязаны совпадать только финальные файлы `result/dataset.xlsx` и `result/main.xlsx` (если он есть) с колонками из раздела [Выход](#выход-resultdatasetxlsx-и-resultmainxlsx). В корне `result/` лежат только они. Промежуточные файлы, например датасеты для загрузки в sandbox-таблицу и выгрузки запросов, лежат в `result/temp/`.
- Всё остальное у каждого периода своё: формат сырых выгрузок, скрипты, промежуточные файлы и поля, правила отбора и дедупликации, SQL-запросы, подпапки. Подход у периодов может совпадать, но решения одного периода не переносятся в другой по умолчанию.
- Папки не ссылаются друг на друга и на общие скрипты. Код, который нужен периоду, копируется в его папку.
- Датасеты для загрузки в sandbox-таблицу скрипты сохраняют в CSV с разделителем `;`, в кодировке UTF-8, первая строка — заголовки.
- Скрипты строят пути от папки периода (`Path(__file__).parent.parent`), поэтому их можно запускать из любой директории.

Скрипты написаны под Python 3.14 с `pandas` 2.3 и `openpyxl` 3.1.

## Power Query

В `power_query/` лежит код Power Query (M), который вставляется в книгу Excel с уже загруженными финальными датасетами. Код не читает файлы и папки: он работает с двумя таблицами книги, `dataset_prev` ("было") и `dataset_curr` ("стало"). Чтобы сравнить другую пару периодов, достаточно подменить данные в таблицах, код не меняется.

В [`power_query/README.md`](power_query/README.md) описано, какие показатели считаются, как устроена сводная таблица и строки "без влияния пула", как собрать книгу для новой пары периодов и как оформить новый раздел в `docs/ru/results.md`.

## Стиль SQL

- Диалект Vertica.
- Ключевые слова, функции, алиасы и идентификаторы в нижнем регистре.
- Цепочка CTE через `with`, приведение типов через `::`, отступ 4 пробела, каждое поле на своей строке, явные алиасы таблиц.
- Имя sandbox-таблицы меняется от загрузки к загрузке, поэтому оно стоит только в одном месте запроса, в первом CTE.

## Выход: `result/dataset.xlsx` и `result/main.xlsx`

Единственный контракт между периодами, строка на тикет. `dataset.xlsx` есть в каждом периоде и собирается из всех категорий сырых выгрузок. `main.xlsx` собирается только из категории `main` и есть только там, где сырые данные разложены по категориям. Если все категории приходят одной выгрузкой, как в `2026_w42-46/`, период отдаёт один `dataset.xlsx`.

Колонки у обоих файлов одинаковые. Каждая папка периода отдаёт эти колонки с этим смыслом, иначе периоды нельзя сравнить в Power Query. Как они считаются, решает период.

| Колонка | Смысл |
|---|---|
| `ticket_id` | номер тикета, без дублей |
| `state_date` | дата тикета в периоде |
| `log`, `com` | пометки проверки из сырых выгрузок, без изменений |
| `is_checked` | 1, если `log` не пустой, иначе 0 |
| `net` | изменение сумм по тикету в USD со знаком, 0 если изменений нет |
| `gross` | `abs(net)` |
| `is_error` | 1, если `gross > 0`, иначе 0 |
| `is_mail` | 1, если по тикету было письмо, иначе 0 |
| `mail_sum` | `amount_sell` в USD при `is_mail = 1`, иначе `null` |
| `is_dispute` | 1, если есть хотя бы один платёж с флагом диспута, иначе 0 |
| `dispute_sum` | сумма таких платежей в USD при `is_dispute = 1`, иначе `null` |

Флаги 0/1 и `null` в суммах там, где события не было, нужны, чтобы Power Query считал доли суммой флага, а среднее по суммам без дополнительных фильтров. RVI = `gross_sum / N` = `er × gross_avg`, где `er` (error rate) — доля `is_error`, а `gross_avg` — среднее `gross` по тикетам с `is_error = 1`. Остальные показатели сравнения описаны в [`power_query/README.md`](power_query/README.md).
