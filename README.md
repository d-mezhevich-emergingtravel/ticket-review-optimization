# 🎯 Оптимизация процесса проверки тикетов

Проект сокращает число тикетов CRM (продукт Hotel, категории Incident и Complaint), которые специалист проверяет вручную. Он состоит из двух частей:

- **[Исследование](docs/ru/research.md)** — есть ли смысл сокращать ручную проверку и где проходят границы проверки по сумме потерь.
- **[Новый workflow проверки](docs/ru/workflow.md)** — гибридная модель, построенная на выводах исследования: специалист проверяет все тикеты за порогом по сумме потерь, а ниже порога только тикеты, в которых алгоритм нашёл вероятную ошибку. Работает с 1 октября 2026.

Начать лучше с [обзора проекта](docs/ru/README.md): идея, задачи и «было → стало».
